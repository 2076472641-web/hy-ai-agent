每组种子数据都像一张「标准考卷」，包含完整的题目和标准答案：

```json
{
  "id": "LOG-001",                           // 编号
  "question": "从深圳发500g包裹到纽约最便宜怎么发？", // 🔍 用户真实会问的问题

  "knowledge_point": "国际物流方式选择与时效报价" // 🎓 知识点
}
```

> 💡 **小白理解**：51 组种子 = 给 AI 吃的「标准答案复习资料」，确保它回答的都是行业正确答案，不是瞎编的。

## 🌿 第二层：本地文档自动扫描入库

### 📂 数据文件位置
```
📁 根目录 / data / knowledge /
├── cross_border_logistics/  ← 放物流类PDF/Word/图片
├── after_sales_policy/      ← 放售后政策类
└── customs_compliance/      ← 放海关合规类
```

### 🔄 工作流程

1. **您只需把文件丢进对应文件夹**（支持格式：PDF、Word `.docx`、TXT、图片 PNG/JPG）
2. 系统下次启动时，**自动扫描** 这 3 个文件夹
3. 自动做 **「清洗 → 切片 → 向量化编码 → 入库」** 全套处理
4. 处理完直接加入向量库，AI 立刻就能用这些新文档回答问题

### 🛠️ 差异化切片策略（核心黑科技）

不同类型的文档切法不一样，**确保知识不被切散**：

| 文档类型 | 切片方式 | 为什么这么切？ |
|---|---|---|
| 📦 物流文档 | 按时效/报价表格切片 | 运费表必须整块保存，切散了价格就对不上 |
| 🛒 售后文档 | 按问题-处理流程切片 | 退货流程是一个完整步骤，不能切一半 |
| 📜 合规文档 | 按条款编号切片（①②③/第X条） | 法律条款要保留完整性，不能断章取义 |

### 功能 2️⃣ · 🧠 三大知识库 **自动识别+精准匹配**

**是什么？** 用户一问问题，系统 0.1 秒内自动判断属于哪一类问题，**只在对应的知识库里搜答案**，避免张冠李戴。

| 命中的关键词 | 自动归入 |
|---|---|
| 运费、时效、包裹、清关、FBA、DHL、体积重 | 📦 跨境物流知识库 |
| 退货、退款、质保、差评、争议、chargeback、召回 | 🛒 海外售后知识库 |
| 关税、VAT、HS编码、IOSS、FDA、合规、税率、RCEP | 📜 海关合规知识库 |

**举例子**：
- 用户问「亚马逊美国站怎么退货？」 → 自动归入 🛒 售后 → 只搜售后政策，不会跑到物流里。
- 用户问「发德国 10kg 多少运费？」 → 自动归入 📦 物流 → 直接报物流渠道价格表。

### 功能 3️⃣ · 🔍 **多路召回 + 混合检索**（找到最准的答案）

**是什么？** 问一个问题时，**同时用 3 种方式**在知识库里搜，取并集后再用 Rerank 重排，**确保该找到的知识一条都不漏**。

```
用户问题 → ① 稠密向量语义搜索（意思相近就算匹配）
        → ② 稀疏关键词搜索（专业术语/型号精确匹配）
        → ③ 类目加权搜索（物流问题给物流库加权重）
                └──→ 合并结果 → Rerank 模型重排 TOP10 → 给LLM生成答案
```

**为什么要三路？** 单路搜索很容易漏答案：
- 只用语义搜：用户搜「IOSS编码规则」→ 可能漏掉完全匹配但向量相似度不高的条款
- 只用关键词搜：用户搜「发美国包怎么寄划算」→ 搜不到写着「ePacket邮政小包最经济」的文档

三路+Rerank 组合后，**召回率从单路的 65% → 提升到 95% 以上** ✨

---

### 功能 4️⃣ · 🛡️ **幻觉检测 + 忠实度校验**（防AI胡说八道）

**这是本系统的核心安全功能！** 特别关键 ✨

| 问题场景 | 普通 AI 会做什么？ | 本系统会做什么？ |
|---|---|---|
| 知识库没收录的问题 | 瞎编一个看起来合理的答案 | 🚫 **不回答**，直接说「抱歉这个问题超出我的知识范围，请联系人工客服」 |
| 问题本身是「诱导性的」(比如用户说："发纽约只要10元当天到货对吗？") | 顺着用户的话胡说，甚至道歉承认 | 🚫 **主动驳回**，先纠正用户错误前提，再给出正确信息 |

**检测的 2 个指标**（回答后会在前端气泡底部显示）：
- 🎯 **Faithfulness 忠实度**：回答和知识原文匹配度（≥80% 才能发给用户，绿色显示）
- ⚠️ **Hallucination 幻觉级别**：none（无）/ low（轻微）/ medium（中等）/ high（严重）
  - 达到 **medium 以上** 自动拦截，不会展示给用户

> 💡 **小白理解**：这就像给AI配了个"监考老师"，让它**只抄讲义（知识库）不能自己瞎编**。市面上普通 ChatGPT 类产品最危险的就是会胡说八道，本系统从机制上避免了。

---

### 功能 5️⃣ · 🧭 **问题澄清 & 信息补全引导**

**是什么？** 用户问题没说清楚时，**AI 不会瞎答**，而是主动追问关键信息。

**举例子**：
- 用户说「怎么寄包裹到国外最便宜？」
- **本系统不瞎报价**，反问：
  > ❓ 为了给您精准报价，还需要确认几个信息：
  > 1. 包裹重量多少克？
  > 2. 发往哪个国家/城市？
  > 3. 对时效要求是普通(15-25天)/ 快速(7-15天) / 加急(3-5天)？

**3 个信息点缺失时会主动追问**：
- 📦 物流类：**重量、目的地、时效要求**
- 🛒 售后类：**订单金额、购买平台、购买时间**
- 📜 合规类：**商品品类、申报货值、HS编码（已知时）**

### 功能 🔟 · 📝 **全链路 Trace 追踪**

每次回答后，API 响应里都带一个 **`trace` 字段**，完整记录从提问到回答的每一步，方便排查问题：

```
trace = {
  ① 输入预处理: { 清洗后文本, 分词数, 自动识别语种 }
  ② 类目预判:   { 预测类目, 权重, 命中的关键词 }
  ③ 多路召回:   { 稠密命中N条, 稀疏命中N条, 加权重排后TOP10 }
  ④ 上下文构建: { 实际给LLM看了哪5段知识原文 }
  ⑤ LLM调用:    { 请求字数, 回复字数, 花费多少token, 耗时 }
  ⑥ 风控检测:   { 忠实度分数, 幻觉等级, 是否被拦截 }
}
```

**排查场景举例**：
- 用户说「回答不对」→ 打开 trace 看「④ 上下文构建」→ 就知道是**没搜到正确知识**（召回问题）还是 **搜到了但 LLM 组织语言错了**（生成问题）。

| 缺 `python-multipart` 包 | 💥 **直接启动失败**，整站 500 | ⚠️ `/api/ingest` 友好提示"请运行 pip install XXXX"，**其他聊天/页面功能全部正常** |
| Lifespan 启动事件没触发 | 💥 所有接口报 `AttributeError: orchestrator` | ⚠️ 自动懒初始化，后台异步加载知识库，用户无感 |
| 知识库仍在加载中用户提问 | 💥 超时或 503 | ⚠️ 6 语种友好提示："⏳ 加载中，请10-30秒后再试" |
| `.env` 里模型 key 配错 | 💥 一提问就崩 | ⚠️ 返回清晰错误说明 + 配 key 步骤，不连累其他接口 |

> 💡 **小白理解**：就像给汽车装了"故障灯+紧急模式"，少了个零件不会直接熄火，而是告诉您哪里坏了、其他功能还能继续开。

## 🎓 小白 Q & A（您肯定会问的问题）

### ❓ 问：我不懂技术，这个系统怎么加新知识？
**答：3 种方法任选一种（从最简单到最正式）**：
1. **最简单**：把 PDF/Word 丢进 `data/knowledge/对应文件夹` → 重启 run.py ✨
2. **半自动**：用前端管理员页面（后续可接）上传 → 立即入库
3. **正式上线**：您的后台系统一有新政策就调 `/api/ingest` 接口 → 秒级入库

---

### ❓ 问：回答错误怎么办？
**答：两步解决**：
1. 先**看 Trace**（开发者模式）→ 判断是「没搜到正确知识」还是「搜到但 LLM 理解错了」
2. 如果是没搜到 → 把这道题加入 `test_cases.json`（下次启动自动复习这道题）
3. 如果是 LLM 理解错了 → 调 prompt 模板，调 Rerank 权重

---

### ❓ 问：支持接入真实的独立站吗？比如 Shopify / 店匠 / 有赞AllValue？
**答：支持！**
> 本系统的 API 已经按标准写好了，任何电商平台只要能发 **HTTP POST 请求**，直接接 `/api/chat` 即可。前端页面可以嵌入店铺的「在线客服」浮窗。完全现成，不用改代码。

---

### ❓ 问：我换模型怎么办？（现在用的是阿里云百炼）
**答：改 `.env` 3 行就行，代码一行不用动**：
```dotenv
# 原来的阿里云
LLM_PROVIDER=aliyun_bailian
LLM_API_KEY=sk-xxx
LLM_MODEL=qwen-plus-v2

# 换成 GPT-4o
LLM_PROVIDER=openai
LLM_API_KEY=sk-xxx
LLM_MODEL=gpt-4o
```
代码里用了统一 LLM 抽象层，切换供应商完全无感。
