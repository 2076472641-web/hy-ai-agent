# 技术栈小白讲解手册 — 优店汇商品类目分类系统

> **阅读说明**：这是给完全没学过算法的人看的，全程只用生活类比，不用公式。
> 每一章讲完都会说「你面试的时候只需要说这一句」，你背那句话就行。

---

## 🌰 先定一个最大的类比：把项目想成「给新来的员工做岗前培训」

整个项目干的事就是：**我训练了一个机器人员工，让它看商品的标题和详情，然后判断这个商品属于服装/数码/美妆……的哪一类。**

类比场景：
- 你开了一家超市，招了个理货员（这就是我们的模型）
- 理货员的工作 = 拿到一件商品，看一眼名字和介绍，然后放到货架正确的位置上
- 一开始理货员是小白，经常放错；我们的工作就是**通过各种方法把它训练成老员工**

接下来讲的所有技术，全都是围绕「怎么训练理货员、怎么让理货员干活更快更准」展开的。

---

## 📦 第一部分：数据预处理（理货员上岗前的"打扫卫生"）

### 这一步在干啥？
真实世界里的商品标题和详情非常脏——里面有：
- 网页代码痕迹 `<span>包邮</span>`
- 表情符号 😊🎉（用户瞎写的）
- 繁体字、全角数字（不统一机器会以为是不同的字）
- 重复标点「！！！！好便宜！！！」
- 一堆没用的废话"亲欢迎来到本店"

**类比**：理货员看商品名称的时候，你得先把包装上的污垢、贴纸、广告语都擦掉，只留「品牌+是什么+多大码」这些核心信息，不然理货员注意力会被垃圾信息分散。

### 12步清洗流水线是什么？（不用记12步，记目的）
就是按顺序擦12次灰：
```
HTML解码 → 剥标签 → 去URL邮箱 → 去emoji → 繁简转换 → 全角半角转换 →
特殊字符过滤 → 重复标点压缩 → 空白归一化 → 太短的扔掉 → 分词 → 去停用词
```

### 关键术语翻译（小白版）

| 术语 | 大白话 | 你面试时只要说这一句 |
|------|--------|-------------------|
| **HTML实体解码 + 剥离标签** | 把"&lt;"这种网页代码变回正常中文，把`<b>加粗</b>`这种标签刮掉 | "先把从网页爬下来的代码符号清理干净，保留纯文本" |
| **jieba_fast 分词** | 中文不像英文有空格，「红色纯棉卫衣」得切成「红色/纯棉/卫衣」三个词，不然机器以为是一整个没见过的怪词 | "用jieba_fast把句子切成一个个词，这是中文处理的第一步" |
| **停用词过滤** | 像"的、了、啊、欢迎来到本店"这种对分类毫无帮助的废词，直接删掉别占位置。我们做了200+电商专属废词表（比如"包邮""秒杀""拍下立减"这些运营常用但对分类没用的词） | "把'的、包邮、秒杀'这种废词过滤掉，减少噪音" |
| **分层抽样 8:1:1** | 把所有商品分成3堆：8堆用来教理货员（训练集），1堆用来边教边考试（验证集），1堆用来最终大考（测试集）。分层的意思是每堆里服装/数码/美妆的比例都一样，不然会出现"训练集里没宠物用品却考宠物用品"的不公平情况 | "按8:1:1切分训练/验证/测试集，用分层抽样保证每类比例一致，评估更公平" |

### EDA 6类图表是什么？
EDA = 探索性数据分析。说白了就是**先看一眼数据长啥样，再决定怎么训练**，不然瞎训练就是盲人摸象。
- 类目分布图 → 看12类各有多少条（发现服装多、宠物少 → 后面要解决样本不均）
- 文本长度图 → 看标题和详情有多少字（发现详情太长 → 后面要解决截断）
- 高频词柱图 → 看"纯棉""蓝牙"这些词出现多少
- 词云 → 可视化看一眼每类最常见的词
- 热力图 → 看词和类的关联程度

## 🎨 第二部分：特征工程（给理货员划重点："看这里！看这里！"）

### 这一步在干啥？
理货员不能直接看一整句中文，它是个"笨家伙"，只能看懂数字。所以我们要先把文字转换成数字，这个过程叫「特征提取」。

### 类比
你培训理货员的时候，不是把整段话给他背，而是告诉他：**"你判断的时候重点看这几个信号，出现这些词就大概率是哪类"**：
- 出现"毫升ml、保湿、口红、粉底液" → 美妆类
- 出现"蓝牙、充电、续航、128G" → 数码类
- 出现"码、纯棉、卫衣、牛仔裤" → 服装类

这些"信号"就叫特征。特征工程就是**人为给理货员划重点**，告诉它看什么。

### 双路径 FeaturePool 特征池（大白话）

#### 🌲 无监督路径（4种特征组）—— 不用人教的抓重点方式

| 特征 | 大白话 | 面试一句 |
|------|--------|---------|
| **词级TF-IDF（5000维 1-2gram）** | 计算每个词"在某类里出现得特别多、但在所有类里又不是很常见"的程度。比如"粉底液"只在美妆里高频 → TF-IDF分特别高；"好的"到处都有 → TF-IDF分特别低。1-2gram就是同时看单个词+相邻两个词的组合。 | "用词级TF-IDF提取关键词，5000维1-2gram，词重要性越高权重越大" |
| **字符级TF-IDF（2-4gram）** | 上面是切词后看，这个是不切词、按2-4个字的连续片段看，用来抓词的形态——比如"蓝牙耳机""蓝牙音箱"里的"蓝牙"这两个字连在一起就是强信号。有些词没切好但字符重叠也能抓住。 | "再加字符级2-4gram的TF-IDF，双路拼接互补" |
| **BERT嵌入（CLS/Mean-Max双池化）** | 把整段话送进BERT这个"超级老师"，它会吐出一串768维的数字向量（你不用懂多少维，就理解成"BERT给这段话打了768个分数标签，每一个代表某种语义属性"）。取CLS位或者Mean+Max池化（取平均+取最大）两种方式把向量压缩好。 | "再加BERT嵌入，用CLS和Mean-Max双池化抽取深层语义特征" |
| **Ngram词频** | 简单粗暴数每个词/词组出现多少次。和TF-IDF的区别是它不加权，纯次数。 | "最后加Ngram词频特征，4组特征统一拼起来" |

把这4种特征拼接在一起，就是一个巨大的数字表格，这就是我们的「FeaturePool特征池」。

#### 🎯 有监督路径（卡方、互信息、树模型重要性Top-K筛选）—— 有人教的抓重点方式
上面4组拼完可能有几万维特征，太多了理货员记不住，需要**筛选掉没用的**。
- **卡方检验**：检验"这个词出现"和"属于这个类"是不是有关系。比如"蓝牙"出现和是不是数码类强相关 → 留着；"你好"出现和任何类都没关系 → 砍掉。
- **互信息**：类似，计算两个东西之间的"依赖程度"。
- **树模型重要性**：先跑一遍随机森林，它会自动告诉你"分裂节点时哪些特征最有用"，取Top-K。

#### 🧹 冗余剔除（低方差 + 高相关贪心剔除）
有些特征是双胞胎——比如"蓝牙"和"蓝牙耳机"几乎总是一起出现，高度相关，留一个就行。
- 低方差过滤：某个特征取值几乎不变（比如某列全是0或全是1）→ 直接扔，没有信息量。
- >0.95高相关贪心剔除：算所有特征两两之间的相关系数，如果两个特征太像（>0.95），就扔掉其中一个。

#### 🏆 LGBM + 3折CV 暴力枚举
最后一步：把所有保留的特征做一个"排列组合大比赛"——用LGBM（一种很快的树模型）加上3折交叉验证，把"单独用词TF-IDF、用字符TF-IDF、用词+字符、词+字符+BERT……"所有排列组合全试一遍，看哪一种组合的F1最高，就选它。

**面试一句总结特征工程**：「我构建了双路径FeaturePool，无监督抽4类特征、有监督做Top-K筛选，冗余剔除后用LGBM+3折CV暴力枚举选出最优特征组合。」

## 🤖 第三部分：多模型训练（四种理货员，选最好的那个）

### 类比：4种不同水平的理货员
我们一共训练了**4类模型 = 4种不同水平的理货员**，然后挑最适合超市用的那个。

### 模型1：随机森林（Random Forest） 🌲🌲🌲
**类比**：一个很勤奋但脑子有点笨的老员工。他不理解语义，就靠「死记硬背关键词」干活——
"我记了5000个词：出现蓝牙我投数码一票，出现粉底液投美妆一票……最后投票最多的就是结果"。
- 200棵树 = 200个老员工投票；max_depth=30 = 每个人最多记30层判断逻辑，别记太细过拟合；
- class_weight=balanced = 给冷门类目的投票加权，防止大家都投热门。

**优点**：上手快、便宜、能看"这个词权重多少"（可解释性强）。
**缺点**：不认同义词——"老爹鞋"它没见过"爹"字出现在鞋类里，就容易分错；语义理解力为0。
**效果**：F1约0.88。

**面试一句**：「随机森林用TF-IDF拼接特征，200棵树、max_depth=30、class_weight=balanced做基线，可解释性强训练快，但语义理解弱。」

---

### 模型2：FastText ⚡
**类比**：一个反应超快的兼职员工，记忆力不好但反应极快。
- wordNgrams=2 = 同时看单个词和相邻两个词的组合，比纯看单个词准一点；
- dim=128 = 每个词压缩成128维的向量（相当于每个词128个属性值）；
- bucket=20万 = 没见过的词（OOV）按字符哈希到桶里，防止词表无限膨胀。

**优点**：快得离谱！30秒就能训完一个模型。模型体积只有几MB，手机都能跑。
**缺点**：和RF一样，语义弱，不认复杂隐含关系。
**效果**：F1约0.84。

**面试一句**：「FastText作为轻量基线，wordNgrams=2、dim=128、bucket=20万，训练30秒、模型几MB，但F1只有0.84。」

---

### 模型3：BERT微调 🧠⭐（最后选了它当主力！）
**类比**：一个清华毕业的学霸实习生。
- 别人花了几千亿个token、几千张GPU、几个月时间把它教出来（预训练阶段）——这相当于它已经读完了整个互联网的所有中文资料，天然就懂"老爹鞋是鞋子的一种款式"这种知识。
- 我现在做的"微调" = 不是让它重新学，而是**拿着我的12类电商数据，专门再补习2-3轮电商分类课**——只需要调最后几层参数，相当于"给学霸做一套电商真题卷子"。
  - max_length=128 = 每段话最多只看前128个字（电商够用了，前面详细讲过原因）；
  - LR=2e-5 = 学习率，步长超小，因为它基础很好，不用改太多；
  - warmup=0.1 = 前10%的训练步数学习率从0慢慢涨上来，防止一下子改太多崩掉；
  - 权重衰减0.01 = 防止参数太大过拟合；
  - 梯度累积2步 = 相当于把batch size翻倍但显存只占一半；
  - FP16混合精度 = 用半精度浮点数加速，省显存提速。

**优点**：语义理解天花板级！"老爹鞋""神仙水""小蜜罐"这种隐含品类词它都认得。
**缺点**：贵、慢、体积420MB、单条CPU推理120ms。
**效果**：F1=0.957（比RF高8个点！）

**面试一句**：「主力用bert-base-chinese做3轮微调，max_length=128、LR=2e-5、warmup=0.1、权重衰减0.01、梯度累积2步+FP16，F1冲到0.957，比基线高8个点。」

---

### 模型4：通用大模型Prompt工程 🤖❌（试了但放弃了）
**类比**：去外面请了个咨询顾问（通用大模型），人家什么都会，但让他帮你理货——
1. 他不知道电商细分术语（"小蜜罐"他以为是蜜蜂窝不是面霜）；
2. 你要把12类的详细定义+例子全塞给他，但窗口塞不下，给不全他就瞎蒙；
3. 每问一次他收你1块钱，自己训的BERT一次成本才1分，**差60-80倍**；
4. 他思考还要1-2秒，BERT只需要38毫秒，**慢10-20倍**。

所以最后没采用。只保留了LLM后续做Agent的方向。

## ⚡ 第四部分：模型轻量化三档方案（让学霸理货员跑得又快又便宜）

现在问题来了：BERT学霸效果好，但雇他太贵（机器贵）、干活太慢（大促忙不过来）。
**我们的目标：以几乎不损失准度为代价，让他又快又便宜。**

类比：把一个年薪百万的博士（12层BERT），培训出一个年薪30万的硕士（6层蒸馏BERT），干同样的活，正确率只差千分之八。

### 一档：INT8动态量化（减肥瘦身法）💧
**类比**：博士脑子里想的都是精确到小数点后7位的数（FP32浮点数）。
但理货员判断"这是美妆还是服装"根本不需要那么精确——小数点后0位（整数INT8）就够了。

把模型里Linear层和Embedding层的权重从32位浮点数压缩成8位整数：
- 体积：420MB → 110MB（缩小3.8倍）📦
- 延迟：120ms → 48ms（快2.5倍）⚡
- 准度：F1只降0.006（你感觉不出来的程度）🎯

动态量化 = 不用校准数据，直接压。静态/QAT更准但麻烦，电商分类动态就够了。

**面试一句**：「一档用INT8动态量化，压缩Linear和Embedding权重，3.8倍体积、2.5倍速度，F1仅降0.006。」

---

### 二档：DistilBERT知识蒸馏（名师带徒法）👨‍🏫
**类比**：我们有12层的教师BERT（420MB学霸）。
现在训练一个6层的学生DistilBERT（240MB），怎么教呢？

不是直接拿标答教学生（那就是普通的训练），而是：
1. 让教师做题目，**不仅给标答（真标签0或1），还给教师自己的"置信度"（比如80%是服装15%是鞋5%是其他）**——这叫软标签，包含了教师的"解题思路"，比硬标签信息量大。
2. 温度 **T=4**：把教师的软标签"拉大差距"（数学上除以T再softmax，再乘回来T²保持梯度）。T=1的话软标签和硬标签差不多，T太大又模糊。4是经典值。
3. **α=0.5**：学生的总损失 = 50%学生和教师软标签之间的KL散度差异 + 50%学生和真标签的交叉熵。意思是"既要学老师的思路，也要听标准答案"。

结果：
- 参数：108M → 66M（少了近一半）
- 延迟：120ms → 46ms（快2.6倍）
- **F1：0.957 → 0.949（只降千分之八！）** 🎉

**面试一句**：「二档用DistilBERT知识蒸馏，T=4、α=0.5，损失0.5×KL(T)×T² + 0.5×CE，参数量少40%，速度快2.6倍，F1只降0.008。」

---

### 三档：ONNX导出+动态batch（流水线优化法）🏭
ONNX = 一种通用的模型格式，不管你是PyTorch还是TensorFlow训的，导出成ONNX就能到处跑，而且专门做了推理加速。

- 动态batch = 一个人过来我就一件一件干；100个人排队我就批量一起干（batch=64），并行处理。
- 原来PyTorch batch=64时吞吐量85条/s → ONNX优化后320条/s（**快了3.8倍**！）
- 单条延迟从48ms → 38ms。

**面试一句**：「三档ONNX导出+动态batch=1-64自适应，batch=64时吞吐量从85条/s升到320条/s，快3.8倍。」

---

### 最终部署方案 = 蒸馏+ONNX双剑合璧
- 体积：420MB → 240MB（↓43%）
- 延迟：120ms → 38ms（↓68%）
- 吞吐量：↑3.8倍
- F1：0.957 → 0.949（几乎没降！）
- 大促1000QPS：原来要6台4核8G机器 → **现在只要2台**（省了2/3服务器钱）

## 📏 第五部分：评估指标（怎么判断理货员干得好不好）

### 类比：理货员年终考核，不能只看"正确率"
6维综合评估：

| 指标 | 大白话 | 面试一句 |
|------|--------|---------|
| **Accuracy 准确率** | 100件货放对了多少件。但这个指标不公平——如果100件里有80件服装，理货员闭着眼全放服装也有80%的Acc，但这货根本不合格。 | "Accuracy只能看整体，但大类多的话容易虚高" |
| **Precision-Macro 精确率** | 每类独立算"你放到这个类里的货，真的是这类的比例"，然后12类求平均。比如"美妆类你放了10件，8件是对的" → 美妆Precision=80%。 | "Macro-Precision：你判断是这类的，真的是这类的比例，12类求平均" |
| **Recall-Macro 召回率** | 每类独立算"真的是这类的货，你找到了多少件"，然后12类求平均。比如"真的有10件美妆，你找到了8件" → 美妆Recall=80%。 | "Macro-Recall：所有这类的货，你成功挑出来的比例，12类求平均" |
| **F1-Micro** | 把所有类的TP/FP/FN合并在一起算F1，相当于加权的Acc，大类影响大。 | "Micro-F1全局合并算，大类占比高" |
| **F1-Macro** ⭐核心指标！ | 先算每类的F1（Precision和Recall的调和平均），然后12类**不加权直接求平均**。意思是"服装类和宠物用品类在我这里地位一样"，完美解决了样本不均时大类刷分的问题。 | "核心指标F1-Macro，每类算F1再简单平均，小类目权重一样，最公平" |
| **完整分类报告** | 每一类单独的P/R/F1表格，一眼就能看出哪类弱（比如初期宠物用品F1只有63%，一眼就看到）。 | "配合完整分类报告，一眼定位哪个类目效果差" |

**面试核心指标一句话**：「我用6维综合评估，核心用F1-Macro而不是Accuracy，因为它给每个类目相同权重，对样本不均的小类目更公平。」

### CLI工具链（7个命令）

类比：理货员入职的SOP操作手册，不用东跑一个命令西跑一个脚本，一键走完入职流程。

### FastAPI接口（4类接口）
给后端/前端调用的HTTP接口：
1. 单条分类：传一个商品，返回是哪类+置信度
2. 批量分类：传1000个商品一起分类（大促用）
3. 模型管理：切模型版本、看当前用的是哪个
4. 运营纠错反馈：运营发现分错了，点一下"报错"，这条错样本直接存进feedback.csv，下次增量训练用上

### Streamlit可视化后台
给运营同学用的网页：输入商品标题→实时返回分类结果+每类的置信度柱状图。不用懂技术就能用。

### ModelManager多模型热加载
内存里同时装着RF、FT、原生BERT、蒸馏BERT……好几个模型，随时切，不用重启服务器。版本管理像切Git分支一样。

### BaseClassifier抽象基类
所有模型（RF/FT/BERT）都继承同一个接口：必须实现 init / train / predict / evaluate / save / load 这6个方法。好处是什么？**以后新同学想加一个TextCNN模型，只需要实现6个方法，就能无缝接入训练、压缩、评估、部署全流程，不用改其他地方一个字。** 这就是"开闭原则"——对扩展开放，对修改关闭。

### seed_everything(42) + config.yaml
- seed=42：把numpy/torch/random所有随机种子固定为42。这样任何一台机器、任何人跑你的代码，只要用同样的参数，F1分数就一模一样。**可复现！**（面试官非常看重这一点，因为很多人做实验跑了就忘，别人复现不出来。）
- config.yaml：所有超参数（max_length、LR、batch_size……）都在这个yaml文件里，不写魔法数字。改参数不用动代码，改配置文件就行。

## 🎯 三个经典问题的再回顾（用小白版逻辑串起来）

### ❓问题1：文本长短差异大 → 怎么想到max_length从512降到128？
"一开始我也信了BERT默认512，后来做EDA发现——电商标题才10-30字，详情虽然长，但前面的卖点和后面的规格参数才有信息量，中间一大段故事性描述都是水。我先做了加权合并（标题+SEP+详情前60%+SEP+详情后40%）保证标题100%在，然后实验对比64/128/256/512四档长度，发现128的时候F1反而最高。后来想通了：长度一长，BERT注意力被一堆没营养的词分散了，短一点反而注意力集中在关键词。"
→ 数字脱口而出：**F1高0.3个点，速度快3.2倍，长尾规格品错误率从11.2%降到3.8%。**

### ❓问题2：样本不均衡 → 为什么换Macro-F1指标这么重要？
"一开始用Accuracy看着挺高，但看分类报告发现小类目宠物用品召回才63%，相当于10件宠物食品它只认对了6件。原因是服装样本是宠物的3倍，模型图省事，把模糊的全押服装，Acc好看但实际不好用。数据层我用stratify分层抽样保证每折每类比例一致，算法层class_weight加大小类惩罚，最关键是把指标从Accuracy换成F1-Macro——这样12类每类一票，模型想靠押服装刷分刷不动了，必须老老实实把小类目也学好。"
→ 数字脱口而出：**12类F1标准差从0.18降到0.06，宠物用品F1从63.2%升到89.7%，整体Macro-F1升4.6个点。**

### ❓问题3：原生BERT太慢 → 为什么选「蒸馏+ONNX」不是只用量化？
"一档量化最快最简单，但只压权重不压层数，3.8倍压缩、2.5倍加速。二档蒸馏是从结构上瘦身，12层变6层，2.6倍加速、几乎无损，但蒸馏要再训一轮，麻烦点。三档ONNX不改变模型本身，纯格式优化+动态batch，吞吐量能翻4倍。线上我把二档+三档组合了——先用蒸馏压模型，再用ONNX优化推理。单独用量化能省2/3机器，蒸馏+ONNX能省到2台，部署压力最小。"
→ 数字脱口而出：**延迟↓68%，吞吐量↑3.8倍，大促1000QPS 6台变2台。**
