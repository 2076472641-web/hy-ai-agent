# 途景汇文旅多智能体系统 - PLUS 架构规格书

## 一、 项目核心主线 (Core Principles)

本系统致力于解决文旅场景下信息服务碎片化的核心痛点，通过 **1个业务入口 + 4项技术突破 + 6维评估指标 + 4类核心工程数字** 构建完整的 AI 业务链路。

### 1. 业务核心：统一 AI 规划入口
解决用户在旅游规划中需要频繁切换天气、路线、票务、景点等分散平台的问题。系统实现：
**用户需求理解 → Agent 意图拆解 → A2A 跨智能体协作 → MCP 实时工具调用 → 真实数据整合 → LLM 方案生成**。

### 2. 四大技术痛点与对策
*   **业务复杂 → Multi-Agent 架构**：将天气、路线、票务、景点等不同职责拆分为独立 Agent，避免单 Agent 挂载过多 Tool 导致的意图混淆与逻辑膨胀。
*   **实时数据 → MCP 协议标准**：采用 Model Context Protocol 对底层 API 进行标准化封装，实现 Agent 与工具服务的深度解耦，提升扩展性。
*   **协作协同 → A2A 通信协议**：自主实现 Agent-to-Agent 交互协议，解决任务跨智能体传递与中间结果协同的难题。
*   **多轮长对话 → 混合存储与压缩**：采用 Redis 高频缓存（规划中）+ MySQL 历史持久化 + 自动上下文压缩策略，平衡 Token 成本与推理延迟。

## 三、 系统评估指标 (Evaluation Metrics)

### 1. 任务效果指标
*   **End-to-End Task Success Rate (端到端成功率)**: 目标覆盖 90%+ 核心旅游场景 Case。
*   **Routing Accuracy (意图路由准确率)**: 针对单意图、多意图、模糊意图的精准识别，目标 95% 以上。
*   **Tool Call Metrics**:
    *   Selection Accuracy (工具选择准确率)
    *   Parameter Validity (参数生成合法率)
    *   Execution Success (工具执行成功率)

### 2. 系统性能指标
*   **响应耗时**: 简单查询（如天气）< 2s；复杂行程规划（跨 3+ Agent）5-8s。
*   **上下文压缩效率**: 触发阈值后 Token 减少比例目标为 40%-60%，显著降低推理开销。

## 四、 业务价值与 ROI

### 1. 三大业务收益
*   **用户侧**: 减少 70% 以上的信息搜索与整合操作成本，实现“一句话完成攻略”。
*   **企业侧**: 自动承担 80% 以上的重复性旅游咨询任务，显著降低人工服务压力。
*   **产品侧**: 基于 MCP 与 A2A 的标准化封装，形成可快速复用的文旅 SaaS 能力，研发交付效率提升 50%。

### 2. ROI 计算模型
**净收益 = (人工成本节约 × 自动化覆盖率) - (GPU/Token 推理成本 + 运维成本)**
